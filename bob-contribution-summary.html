What Was Built
01
API Service Module — src/api.js
All 13 backend functions (getUsage, postTask, postTrace, etc.) wrapped in one module. Every function falls back to realistic local mock data when the backend at localhost:3001 is unreachable, so the UI works fully standalone. No component calls fetch directly.
02
Budget Context + Animated Display
BudgetContext holds global credit state and exposes applyBudgetUpdate and switchScenario. BudgetDisplay tweens the number with a cubic ease-out over 300ms, animates the bar's width and color across green/yellow/red thresholds, and floats a −N / +N badge that fades upward on every change.
03
Workspace Screen (Screen 1)
Chat-style input with Ctrl+Enter shortcut. Calls postTask and navigates to Analysis on success. Shows a completion banner after returning from execution — including the names of any deferred tasks — and clears it as soon as a new request is typed.
04
Analysis Screen (Screen 2) — Decision Panel
Quotes the request back, lists all 6 tasks with cost / AI mode / priority badges. Shows three large stat numbers (Available / Estimated / After completion). Three outcome states: full budget covers all tasks → "Start work"; partial coverage → ranked plan with ✓/⚠/○ indicators and "Use recommended plan"; nothing fits → points to TRACE/Resets instead.
05
Execution Screen (Screen 3) — Full Flow
5-step timeline with ✓/●/○ states and AI mode badges. Right-side panel shows animated budget via BudgetDisplay, current task name, and budget-protection notes. At step 2, surfaces the scripted 401 Unauthorized error inline. "See what this change affects" opens the Impact panel with the proposed fix and affected areas. "Apply fix" deducts 320 credits with animated feedback then resumes the remaining steps automatically. On completion, loops back to Workspace with a summary banner.
06
TRACE Screen — Streaming Investigation
4 stages (Diagnose → Find root cause → Minimal fix → Verify) that stream log lines one at a time (> scanning auth flow…), then resolve each stage into a pinned result line. Only the Minimal fix stage costs 160 credits — deducted with animated budget feedback when it completes. If budget is critical on arrival, offers "Use Usage Limit Reset" and "Activate TRACE instead" side by side. Returns to Workspace with the completion banner.
07
Rewards Screen — Quiz + Milestone Bar
Shows 7-day streak, points, and reset count. Progress bar tracks position within the current 2,500-point window. Quiz question with 4 options — correct answer awards +50 points; if that crosses a 2,500-point multiple, a distinct milestone banner fires and the reset count increments. Wrong answer shows the correct answer plainly with no punishment. Starting points seeded at 2,460 so a single correct answer crosses the milestone during a demo.
08
Sidebar — Navigation + Demo Switcher
NavLinks with active accent highlight. Demo switcher (Safe / Low / Critical / Exhausted) calls postDemoScenario and animates the budget change — the active scenario button is highlighted. Max budget is always pinned to 1,240 so the bar shows the correct ratio in every scenario. Persistent animated BudgetDisplay at the bottom.
Bugs Found & Fixed During Build
Bug Demo switcher set max = data.budget — switching to Critical (180 cr) made the bar show 100% green. Fixed: max is always pinned to 1,240; only budget changes.
Bug Execution panel and TRACE header used raw budget.toLocaleString() with a static bar — no tween, no float badge. Fixed: both now render <BudgetDisplay> so every spend animates consistently.
Bug Milestone progress bar calculated as (nextMilestone − pointsToGo) / nextMilestone — correct only at the first milestone; wrong after crossing 2,500 (e.g. next = 5,000 made the bar half-full when 2,460/2,500 earned). Fixed: always divides by the constant 2,500-point window.
Bug Quiz feedback "N points to next reset" used stale pre-answer state minus awarded points. Fixed: reads from the already-updated rewards state after the API response.
Bug refreshBudget referenced animateTo before it was declared in the context module. Fixed: reordered declarations so animateTo is defined first.
Bug Workspace used a dynamic import() for api.js causing a Vite warning (module already statically imported elsewhere). Fixed: converted to a normal static import.
